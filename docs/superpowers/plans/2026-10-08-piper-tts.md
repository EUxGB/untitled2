# План: озвучка Piper (спек `docs/superpowers/specs/2026-10-08-piper-tts-design.md`)

Каждая задача: сначала падающий тест, потом код, полный `npm test`, проверка мутацией нового теста.

1. **Список текстов** — `tests/tts-texts.js` → `tests/tts-texts.json`. Статика: фразы (`PHRASE_SETS`, `OLD_PHRASES`), слова (`WORD_SEEDS`,
   `PHRASE_DICT` и формы, слова фраз), город (как `city-phrases-dump.js` + `npc`/`again`/`short`/`none`), `SMALLTALK`, слова уроков `{{…}}`,
   варианты «послушайте». Динамика: числа и цены (`trNumWords` по всем значениям, которые может выдать город), реплики лавки.
   Тест: всё, что произнесено за прогон тестов (`__spoken`), есть в списке.
2. **Генератор** — `tests/tts-build.py`: читает список и манифест ветки `tts-audio`, озвучивает недостающее Piper (tr_TR-dfki-medium), mp3 48 кбит/с,
   проверяет Whisper (`small` для пачки; при расхождении — `large-v3`), пишет манифест и отчёт `tts-report.json`. Разовый полный запуск — отдельный workflow.
3. **CI** — задача `tts` в `tests.yml` перед `deploy`: генерация недостающего, пуш ветки `tts-audio`, копия `tts/` в артефакт сайта.
   Сначала проверить на ветке, потом в `main`.
4. **Сайт** — `speakTr` + манифест (`tts/manifest.json`, грузится один раз, без него — голос телефона), замена четырёх мест синтеза,
   скорость Kulak, тесты (подбор файла, запасной путь, скорость, «Синтез» играет файл).
5. **Проверка живого сайта** — `verify`: манифест и 20 случайных файлов отдаются (200, audio/mpeg).
6. **Лицензия** в «Как пользоваться», запись в CLAUDE.md.
7. **Пользователь слушает** 10–15 файлов из готового набора до публикации в `main`.
